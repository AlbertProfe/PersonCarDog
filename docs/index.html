Java SE Foundation

What it is

The core Java platform (Standard Edition). You write classes, compile with javac, and run with the java command. No frameworks, just pure language features.

Why it is relevant

Everything in the Java ecosystem is built on top of Java SE. You must understand OOP, collections, exceptions, and the JVM before any framework makes sense.

Why it is a good idea to start here

Starting with plain Java forces you to understand the fundamentals. You learn how the language actually works without “magic” from tools or frameworks.

How it works in practice

You create .java files, compile them manually, manage jars yourself, and run the main class. Good for small utilities and learning, but painful for larger projects.

Maven Build Tool

What it is

A build automation and dependency management tool. You describe your project in a pom.xml file and Maven handles downloading libraries, compiling, testing, and packaging.

Why it is relevant

Almost every professional Java project uses Maven or Gradle. It gives you a standard directory layout (src/main/java, src/test/java) that the whole industry understands.

Why it is a good idea

Manual jar management becomes impossible as soon as you need 5–10 libraries. Maven solves “dependency hell”, ensures reproducible builds, and makes collaboration easy.

How it works

You declare dependencies and plugins in pom.xml. Running mvn clean package downloads everything, compiles your code, runs tests, and produces a jar/war. The project structure is standardized.

Spring Boot Maven Modern Apps

What it is

A framework that sits on top of Spring and Maven. It gives you opinionated defaults, auto-configuration, embedded servers (Tomcat/Jetty), and “starters” that pull in the right dependencies with one line.

Why it is relevant

Spring Boot is the de-facto standard for building production Java (and especially web/microservices) applications today. Most companies hiring Java developers expect Spring Boot experience.

Why it is a good idea

It removes huge amounts of boilerplate. You can have a working REST API with a database in minutes instead of hours of XML/configuration. It follows best practices by default.

How it works

You create a project (often via start.spring.io) with a Maven pom.xml that inherits from spring-boot-starter-parent. Add starters, write annotated classes, and run with mvn spring-boot:run or a single executable jar.

Typical student path

Master Java SE first → learn Maven so you can manage real projects cleanly → move to Spring Boot so you can build the kind of applications companies actually use.

Typical learning path for Java students:
Start with core Java SE → add Maven for dependency & build management → move to Spring Boot for modern enterprise / web applications.
